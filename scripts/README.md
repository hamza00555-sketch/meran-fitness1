# حزمة الصور — التوليد والنشر

الحزمة **صور كبيرة فقط**: صورة لكل جائزة (٤٠)، ولحظتَي الاحتفال (رفع المستوى
والرقم القياسي)، وست حالات فارغة. مجموعها ٤٨.

الأيقونات الصغيرة في الواجهة — الترس، السلة، القلم، الأسهم — تبقى كما هي ولا
تدخل الحزمة إطلاقاً: تحويلها إلى صور مُنزَّلة يكلّف نطاقاً ولا يعطي شيئاً.

الصور لا تُخزَّن في هذا الريبو. تُولَّد عبر **Higgsfield**، تُرفع على
Cloudflare R2، ويصفها ملف `manifest.json` واحد. التطبيق يقرأ المانيفست، ينزّل
ما ينقصه، ويتحقق من كل ملف قبل حفظه.

## دورة العمل

```bash
# ١. اطبع البرومبتات (٤٨ صورة بأسلوب واحد)
npm run pack:prompts                 # أو: node scripts/prompts.mjs --json

# ٢. ولّد الصور عبر Higgsfield (GPT Image 2، 1k، high) واحفظ كل
#    واحدة باسم معرّفها: assets-src/ach_a1.png ...
#    أو أعد جلب المولَّد سابقاً — الحزمة الحالية تُبنى بهذا الأمر وحده:
node scripts/fetch-sources.mjs assets-src

# ٣. اقطع الخلفية البيضاء إلى شفافية حقيقية
node scripts/cut-white.mjs assets-src assets-cut   # الأغلفة تمر كما هي

# ٤. ابنِ الحزمة
npm run pack:build -- --src assets-cut --base "$ASSETS_BASE_URL"

# ٥. انشرها
npm run pack:publish                 # جرّب --dry أولاً
```

`pack/` و`assets-src/` مستثناة من git — لكن **`scripts/pack-sources.json`
ليس كذلك**: فيه النموذج ورابط الأصل لكل فتحة. لهذا تُبنى الحزمة كاملة من نسخة
نظيفة من الريبو بثلاثة أوامر، والريبو يحفظ السجل لا البكسلات. مُختبَر: إعادة
البناء من الصفر تعطي **نفس الـ٤٨ تجزئة** بالضبط.

قائمة الفتحات مشتقّة من `src/assets/slots.js`، ومعرّفات الجوائز تأتي مباشرة من
`ACHIEVEMENTS` — فإضافة إنجاز جديد تضيف فتحته تلقائياً، بلا قائمة ثانية تُنسى.

## لماذا اسم الملف هو التجزئة

كل ملف يُنشر باسم `i/<sha256>.webp`. أربع نتائج:

- **التحديث رخيص.** التطبيق يقارن التجزئات؛ تغيّرت ٥ صور من ٤٨ ⇒ ٥ ملفات.
- **الاستئناف مجاني.** «هل عندي هذه التجزئة محفوظة؟» هو كل شرط الاستكمال.
- **الصورة المشتركة تُنقل مرة واحدة.** فتحتان بنفس الصورة = نفس التجزئة = طلب
  واحد، ثم تُنشر على الفتحتين.
- **الكاش أبدي بأمان** (`immutable`) لأن الملف المتغيّر رابط مختلف.

المانيفست وحده قصير العمر (`max-age=60`) — هو المؤشر الذي يجب أن يبقى طازجاً.
ولذلك يُرفع **آخر شيء**: حتى تنتهي كل الملفات، لا شيء يشير إليها، وفشل الرفع
يترك الحزمة القديمة تعمل.

## المنشور حالياً

البَكِت `meran-assets` على Cloudflare R2، والحزمة منشورة عليه:

```
https://pub-189be0412bdd4092aa44be319badfd91.r2.dev/manifest.json
```

هذا هو الرابط الافتراضي في `src/assets/pack.js`، فالبناء العادي يعمل بلا أي
متغيّر بيئة. `VITE_ASSETS_MANIFEST_URL` يتجاوزه عند الحاجة.

**رابط `r2.dev` رابط تطوير**: محدود المعدل وتصفه Cloudflare بأنه ليس للإنتاج.
الانتقال إلى نطاق مخصص لاحقاً رخيص — أعد البناء بـ`--base` الجديد وانشر، لأن
أسماء الملفات تجزئات لا مسارات.

## إعداد البَكِت — مرة واحدة

1. **نطاق مخصص** (R2 → Settings → Public access → Custom domain) — أو
   `Public Development URL` مؤقتاً كما هو الحال الآن.
2. **CORS** — التطبيق يقرأ البايتات بـ`fetch` ليحسب التجزئة، فلا يكفي وصول
   `<img>`:

```json
[{
  "AllowedOrigins": ["https://<your-app>.vercel.app", "http://localhost:4173", "http://localhost:5173"],
  "AllowedMethods": ["GET", "HEAD"],
  "AllowedHeaders": ["*"],
  "ExposeHeaders": ["content-length", "etag"],
  "MaxAgeSeconds": 86400
}]
```

3. الرابط الافتراضي داخل `src/assets/pack.js`؛ لا حاجة لضبط شيء في Vercel.

## لماذا خلفية بيضاء ثم قطع

إذا طلبتَ من GPT Image خلفية شفافة فإنه **يرسم** مربّعات الشطرنج التي تمثّل
الشفافية عادةً — بكسلات معتمة لا شفافية. طلب حقل أبيض مسطّح لا لبس فيه،
و`cut-white.mjs` يحوّله إلى ألفا حقيقية بتعبئة فيضية من الحافة للداخل: الأبيض
الذي يمكن الوصول إليه من الإطار فقط يُمسح، فاللمعة البيضاء داخل الشارة تبقى.

## الاختبار

- `node --test tests/assets.test.mjs` — المحرّك على وحدات ES الحقيقية.
- `node tests/pack.e2e.mjs` — حقن أعطال: قطع الشبكة، ملف تالف، تحديث تفاضلي،
  حذف. يحتاج حزمتَي اختبار من `tests/make-test-pack.mjs`، وهما مبنيتان من صور
  `public/assets` الموجودة أصلاً — صور حقيقية، لا شيء مرسوم للاختبار.
- `node tests/pack.live.mjs` — **البَكِت المنشور فعلاً**: بلا أي fixture، يتحقق
  من CORS والكاش والتجزئة والتثبيت الكامل.

الحزمتان الأوليان تعترضان المضيف، فيجب أن تُبنى fixtures بنفس `--base` الذي
يطلبه التطبيق وإلا خرجت الطلبات إلى الشبكة الحقيقية وتعلّق الاختبار.

## تدقيق مكافأة الراحة

`npm run ledger -- <backup.json> [عدد الأيام] [--date YYYY-MM-DD]`

يطبع، يوماً بيوم، كيف وصل شريط الراحة الاختيارية إلى رقمه: التصنيف
(مؤهل/مدفوع/فائت)، وأثر كل يوم على الـstreak والتقدم والرصيد. الصفوف تأتي من
`computeRecovery` نفسها لا من حساب موازٍ، فلا يمكن أن يتفق التقرير مع نفسه
ويخالف ما يظهر في التطبيق.

نفس الجدول متاح داخل التطبيق: الإعدادات ← إدارة البيانات ← **سجل المكافأة
(تشخيص)**، مع زر لنسخه نصاً.

يحتاج ملف تصدير من إصدار `2.1` فما فوق — النسخ الأقدم لم تكن تحفظ إعدادات
الراحة (`restDays` والنمط)، ولا يمكن إعادة بناء السجل بدونها.

## أغلفة التقرير الشهري

اثنا عشر غلافاً، `cover_01` … `cover_12`، واحد لكل شهر ميلادي. تختلف عن بقية
الحزمة في ثلاثة أمور:

- **ليست مربّعة**: ١٠٢٤×٦٨٨، وهو مقاس ٣:٢ الذي يخرجه المولّد نفسه، فلا يُعاد
  تحجيمها ولا تفقد حدّتها. كل فتحة في `slots.js` تحمل `w` و`h` الآن، و
  `build-manifest.mjs` يقرأهما بدل `--size` العالمي.
- **كاملة الإطار**: لا خلفية بيضاء تُقتطع، فـ`cut-white.mjs` ينسخها كما هي بدل
  أن يمرّرها على التفريغ (الذي كان سيسحقها إلى مربّع ٥١٢).
- **بلا أشخاص وبلا نص**: معدّات وضوء فقط، مع مساحة خالية في الحافة السفلى يجلس
  عليها نص التقرير.

مجموعها ٠.٦٥ ميغا، فالحزمة صارت ٣.٧٩ ميغا بدل ٣.١٥. ومن نزّل الحزمة سابقاً
يجلب الأغلفة وحدها — العنونة بالمحتوى تجعل التحديث تفاضلياً.
